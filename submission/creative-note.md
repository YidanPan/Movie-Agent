# Movie-Agent 创作手记

## 1. 为什么做 Movie-Agent

我们希望把“我有一个电影想法”与“我能得到一个可检查的制作结果”之间的距离缩短。传统的一次性 AI 视频生成往往只给出一个看似完整的片段，却很难解释角色为什么这样行动、镜头之间是否连续、失败后如何恢复，以及最后的文件是否真的符合交付规格。Movie-Agent 因此被设计成一个面向 AI 影视创作的制作工作台，而不是一个只返回文本或视频的按钮。

## 2. 对一次性生成的重新理解

电影创作包含叙事、视觉、声音、剪辑和交付等不同责任。我们把这些责任拆成有边界的阶段，并让每个阶段留下结构化状态。这样，创作者可以先审阅项目设定、对白、视觉规范和分镜，再决定是否进入媒体生成；当外部任务失败时，也能根据任务 ledger、事件序列和版本继续处理。系统关注的不是“自动生成得多快”，而是创作意图能否被保留、错误能否被定位、结果能否被复现。

## 3. 多智能体制作概念

Movie-Agent 当前由七个应用 Agent 协同完成：Director 负责项目边界和节奏，Writer 负责故事与对白，Visual Bible 负责角色、场景和风格连续性，Storyboard 负责把叙事转为镜头契约，Generation 负责受批准的媒体任务，Reviewer 负责结构、版权风险和媒体质量检查，Editor 负责粗剪、字幕、声音与最终交付。Orchestrator 不替代这些职责，而是维护 revision、幂等键、任务状态、质量门和恢复路径，让协作关系能够被观察。

## 4. 生产工作流

工作流从 PLAN 开始，建立 brief、故事世界和角色约束；PREVIS 阶段生成脚本、对白、视觉设定与结构化 storyboard；RENDER 阶段通过 Provider 适配器处理已批准的镜头任务；DELIVER 阶段负责 AI Edit、字幕、声音、质量验证和导出。项目快照采用临时文件替换并保留备份，任务使用 lease、heartbeat 和事件记录，避免重复执行或把中断误判为成功。

## 5. 可靠性工程

我们把生产可靠性视为创作体验的一部分。幂等请求避免同一操作重复创建任务，compare-and-set 保护并发写入，过期租约支持恢复，事件序列帮助用户理解任务经历，失败状态不会被伪装成完成。媒体交付还区分 Source、Working Proxy、Screening Preview 和 Final Master，并使用 FFmpeg/FFprobe 检查分辨率、帧率、像素格式和音频规格。健康检查只返回能力状态，不输出密钥或内部凭据。

## 6. ModelScope 部署

工程以 Docker 方式部署到私有 ModelScope Studio `LuckyPan/Movie-Agent`，应用监听 `0.0.0.0:7860`，运行数据使用 `/mnt/workspace` 持久化。代码仓库与 Studio 的 `main`、`master` 已同步到当前 release commit。当前演示配置明确为 Mock-only：`MODEL_PROVIDER=mock`、`IMAGE_GENERATION_MODE=mock`、`VIDEO_GENERATION_MODE=mock`、`TTS_PROVIDER=none`。这保证评审可以稳定复现规划、审阅、恢复和交付界面，也避免在演示中消耗真实模型额度。

## 7. Mock 演示与真实能力边界

Mock 模式不是伪造真实生成结果，而是为编排、状态机和失败闭环提供确定性替身。真实 Provider 的适配接口、任务提交/轮询/下载边界和前置烟雾验证已经独立审计，但本次提交不会把 Mock 结果描述成 Wan 或其他模型的实时产物，也不会在录屏时临时切换 Provider。真实生成仍需在得到授权、配置密钥并完成独立验收后进行。

## 8. 短片概念：《付费解锁人生》

影片设定在订阅制社会：记忆、亲情、疼痛和告别都被拆成可购买的功能包，算法根据人的脆弱时刻动态定价。主人公为了保留与家人的最后一段真实关系，被迫完成一连串“情感增值服务”，最终发现连告别也被设计成续费入口。冷色商业界面与逐渐失真的家庭场景形成反差，讨论技术商业化如何把人的经验变成商品，并以荒诞和讽刺保留情感反转。该概念是影片交付方向，不等同于当前六镜头 Mock 演示项目。

## 9. 创作过程与 AIGC 说明

本项目由 Movie-Agent 的工程设计、提示词约束、结构化编排、媒体质量门和人工审阅共同完成。AI 用于辅助创意规划、视觉设定、镜头组织和可选媒体 Provider 接入；项目状态、质量判断、交付规格、版权风险和最终发布决定仍需要创作者确认。团队成员、具体素材来源、音乐、声音、模型和最终影片信息应在正式发布前按实际使用情况补齐，不在本稿中虚构。
